# Threshold evaluation

Generated by `scripts/evaluate_threshold.py`: 106 hand-labelled questions across 14 intents (`eval/intents.json`), evaluated leave-one-out on a warm cache: for each question, all the others are already cached.

A hit is **wrong** when the matched question belongs to a different intent, i.e. the user receives someone else's answer. *Precision* is the share of hits that were right; *wrong* is out of all queries. Several intents are deliberate near-misses (reset vs. change password, enable vs. disable 2FA, cancel plan vs. delete account).

## Embedding models

Each model at its own default threshold (most reuse with guards on while at most 1% of queries get a wrong answer). Latency is one query on CPU. Models are ranked by **expected latency per request**: every request pays for an embedding, but only misses pay for the LLM call (assumed 800 ms). A slower model that avoids more LLM calls can be faster overall, and cheaper.
